# Deploying the front desk

A checklist to go from the `redesign` branch to a live service on Render. Work through it top to bottom;
nothing here has to happen until the repository owner has added you (or merged the branch).

## 1. Get the code onto GitHub

1. The repository owner adds you as a collaborator on `newage1340/dealer-chat-widget` (Settings → Collaborators),
   or you send them the branch.
2. Push the branch: `git push -u origin redesign`.
3. Open a pull request `redesign` → `main`. Don't merge it yet: Render can deploy the branch directly for testing.
4. Optional: add an `OPENAI_API_KEY` repository secret (Settings → Secrets and variables → Actions) so
   `.github/workflows/frontdesk-checks.yml` runs the evals on every change. Without it only typecheck and tests run.

## 2. Create the Render service

1. Render dashboard → New → Blueprint → pick the repository and the `redesign` branch. It reads `frontdesk/render.yaml`
   and creates the `frontdesk` web service and the `frontdesk-db` Postgres database.
2. Use the web plan you already pay for. The database's smallest plan is about $6 a month.
3. The old Python service stays as it is until you switch the Twilio numbers over (step 5), so nothing breaks meanwhile.

## 3. Set the environment

Fill these in on the `frontdesk` service (Environment tab). `render.yaml` already lists them.

| Variable | Value |
|---|---|
| `PUBLIC_BASE_URL` | the service URL, e.g. `https://frontdesk.onrender.com` (no trailing slash) |
| `ADMIN_TOKEN`, `SESSION_SECRET` | generated by Render; copy `ADMIN_TOKEN` somewhere safe (it's the admin password) |
| `OPENAI_API_KEY` | the OpenAI key |
| `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_DEFAULT_FROM` | from the Twilio console; `TWILIO_DEFAULT_FROM` is the number texts come from when a business has none |
| `GMAIL_USER`, `GMAIL_APP_PASSWORD`, `NOTIFY_FROM_EMAIL` | the same values the Python app uses, if it already emails through Gmail |
| `ONBOARDING_NOTIFY_EMAIL` | who hears about new sign-ups |
| `ONBOARDING_CODE` | optional; require an invite code on `/onboarding` |
| `STRIPE_*` | leave empty until billing is decided (step 6) |
| `VOICE_PIPELINE` | `twilio_gather` (default) until Deepgram or the GPU machine is approved |

## 4. First start

1. Deploy. The database schema is created on start. Check `https://<service>/health` returns `{"ok":true,...}`.
2. Load the demo businesses (optional): Render → Shell → `node src/main.ts seed-demo`.
3. Bring over real businesses: in the Render shell, `node src/main.ts import-tenants <dir>`. It reads old Python
   tenant files or new ones. Or create them on `/settings`, or have them use `/onboarding`.
4. Sign in at `/settings` (email blank, password = `ADMIN_TOKEN`) and check each business's "Things to check" list.
5. Give each business owner a login (their page → Logins), or let them sign up through `/onboarding`.

## 5. Move phone numbers

For each Twilio number, one at a time, starting with a test number:

1. Twilio console → Phone Numbers → the number → Voice: "A call comes in" → Webhook → `https://<service>/voice` (POST);
   "Call status changes" → `https://<service>/voice/status` (POST).
2. Messaging: "A message comes in" → `https://<service>/sms` (POST).
3. On `/settings`, add the number under the business's Phone numbers.
4. Call and text it. Check the conversation appears on the business page and the summary email arrives.
5. Write down the old webhook URLs first (Vapi or the Python app), so you can switch back in a minute if needed.

Toll-free numbers need Twilio toll-free verification before carriers deliver their texts. Local numbers are cheaper
per minute ($0.0085 vs $0.022) and text right away once registered for A2P 10DLC.

## 6. Billing (when decided)

1. Stripe dashboard (test mode first) → Products: create three monthly prices: the plan ($99), an extra line ($25)
   and staff text alerts ($10). Copy their price ids into `STRIPE_PRICE_BASE`, `STRIPE_PRICE_EXTRA_LINE` and
   `STRIPE_PRICE_SMS_ALERTS`.
2. Developers → Webhooks → add endpoint `https://<service>/stripe/webhook` with events `checkout.session.completed`,
   `customer.subscription.created`, `customer.subscription.updated`, `customer.subscription.deleted`.
   Copy its signing secret into `STRIPE_WEBHOOK_SECRET`.
3. Copy the secret key into `STRIPE_SECRET_KEY` (`sk_test_...` for testing). Redeploy.
4. On a test business: Billing → Subscribe, pay with card `4242 4242 4242 4242`, and check the status turns Active.
   Then switch the keys and prices to live mode.
5. Settings → Billing → Customer portal in Stripe: turn on "cancel subscription" and "update payment method".

## 7. After it's live

- Turn off the old Python service once every number points at the new one, and change the root `Procfile`.
- Merge the pull request into `main`.
- Watch `/settings/quality` for the first week: reply times, fallbacks, and booking rates per business type.
